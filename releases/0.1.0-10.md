# Sovel Desktop 0.1.0-10 Dual Environment

Install Dual Environment from **Settings → Software Update** and restart Sovel. Private Workspace is opt-in. Before setting it up, verify you have a separate administrator account and remove administrative and log-reading group access from the everyday account. An administrator can read a private workspace while it is open. The setup check also flags other administrator-equivalent groups such as `lxd`.

Run the dry run first, adjusting the usernames if necessary. Then run the same command without `--dry-run` from your administrator account and store the recovery key offline.

```sh
sudo sovel-private setup --user nate-lab --normal-user nate --dry-run
```

## Changes

- **Two environments.** Normal Mode has the city desktop and everyday apps. Private Mode runs under a separate Linux account and compositor on its own virtual terminal, with JARED, projects, engineering tools and the spider-emblem wallpaper. Each account has separate clipboard, notifications, search, recent files, thumbnails, display profiles and widget layouts.
- **Encrypted home and backups.** Private Mode uses a systemd-homed LUKS2 image with AES-256-XTS, Argon2id and a recovery key. After exiting Private Mode, `sudo sovel-private backup /path/to/backup` copies the sealed image and writes a SHA-256 checksum.
- **Locking and switching.** Super+Shift+P locks Normal Mode before switching to Private Mode. Super+L in Private Mode waits for the locker to cover every output before quieting JARED, clearing the clipboard, attempting to close the Vault and switching back to the city lock. Exit Private Workspace stops if windows remain open or Vault closure cannot be confirmed. Automatic sealing while locked is optional.
- **Vault.** A second gocryptfs layer inside the private home uses its own passphrase and recovery key. It closes when idle, and Sovel tries to close it on lock. Open files can defer closure.
- **Private layouts.** The second display defaults to an engineering workspace with JARED, projects, tasks and system monitors. Engineering and Research presets are also available. Widgets remain movable.
- **JARED migration.** JARED and Vault are available only from Private Mode. After setup, `sudo sovel-private migrate-jared --from nate` copies your existing JARED data to the encrypted account.
- **Appearance and fixes.** City sign-in and lock artwork, graphite and violet palettes, and updated glass highlights. Settings reads the correct local homed record, and Vault creation returns its recovery key without logging it.

## Validation and limits

- The development VM built the package with Qt 6.10.2 and the system PackageKit Qt library. It upgraded from Workspace with zero package removals. The 19 Dual Environment Python tests passed on the VM.
- The VM verified file access denial for an unprivileged Normal user, the installed Normal JARED guard, session-lock coverage on two virtual outputs and coverage when one was re-enabled. The Vault rejected a wrong passphrase, mounted and closed correctly, and opened with its recovery key. A sealed LUKS2 backup passed its checksum and restored with the account recovery key.
- VT switching is included. In the VM, the Private greeter service started and the Normal desktop locked, but the shortcut run did not confirm arrival on the Private VT. Physical monitor reconnection, sleep and resume, and crash recovery still require verification. An administrator can access an open private workspace.
